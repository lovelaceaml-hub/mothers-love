## Rules that matter on the next change

- Never run a bare `git push` in the main checkout: it tracks `origin/main`, and a push to `main` deploys production.
- No real recognition, submitted name or other personal data in Git, fixtures, screenshots or logs. Tests use fictional records only.
- `/display` and its eleven screens stay the TV view. The 3D world becomes its own surface and never enters the TV playlist (Plan 28).
- Nothing written for Anthony contains an em or en dash.
- The server region is set in `vercel.json` (`sfo1`, beside the database in `us-west-1`). Moving either one apart again costs several tenths of a second on every request.
- On the live host a compressed reply carries a weak tag (`W/"..."`) and a matching conditional request comes back as an empty 304, never as the server's small JSON heartbeat. Browser code that sends `If-None-Match` must accept both (`src/lib/etag.ts`).
- Checks run in the cloud: `.github/workflows/checks.yml`. A pull request names its own test files in its description; complete suites need `full_suite_approved` and Anthony's approval for that run.
- Many browser tests wait for a refresh on the real clock and pass only on Saturday 9:00 to 22:00 and Tuesday 18:00 to 22:00 Pacific (Plan 32's fast windows). A spec that waits for a refresh installs a clock inside a fast window, as `tests/feed/feed.spec.ts` does.
