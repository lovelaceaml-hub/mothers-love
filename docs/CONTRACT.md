## Selected implementation defaults
Technical defaults are selected under the request to use best judgment, not misrepresented as earlier interview approvals. Names permit Unicode, apostrophes, hyphens and multiword first names, 80 graphemes maximum; show first-name-plus-last-initial guidance. Message maximum500 graphemes; payload maximum16KiB. Distinct integer expression IDs1..9 in canonical order. Trim surrounding whitespace, preserve message wording and line breaks, never interpolate markup.

Receipt: heading "Thank you for sharing Mother's Love." Published body "Your recognition has been received and is ready for the campaign display." Held body "Your recognition has been received. Some messages are reviewed before appearing." Unconfirmed response preserves tab-memory draft and logical submission key. New-recognition action clears all fields. No persistent form drafts.

Counting: held contributes0. First valid publication contributes1 recognition and1 for each selected expression. Edits apply vector differences to original publication day. Hidden valid content stays counted. Invalid reverses current vector exactly once. Reinstate invalid requires explicit restore action, reason and remaining lifetime. Permanent delete valid content preserves contribution; deleting invalid/never-published content adds nothing. Purge preserves daily aggregates, removes personal rows and linked contribution/event/receipt identifiers. No post-purge individual adjustment UI.

Personal lifetime168h. Server reads exclude expiry immediately. Purge scheduled each minute, healthy-operation target maximum2min physical deletion lag, overdue becomes admin warning. No personal text in admin action logs; temporary target links removed at expiry, nonpersonal admin activity30days, short rate-limit hashes24h, one-time pairing codes10min, device session30days and revocable. No persistent browser personal cache: memory only. Backup policy depends on final provider and must be disclosed truthfully, with restore closed until purge/revocation checks. No permanent raw backups added.

Public routes: / submission; /privacy concise data policy. Admin /admin, /admin/login, /admin/mfa. TV /display pairs before data access. No browsable public recognition wall. Browser-local demo route only when explicitly enabled in development/test, never production. Server unavailable/configuration missing: collection closed with truthful message, never pretend saved. Admin preview receives public projections separately from private details.

## Stable cross-lane interfaces
Foundation owns src/lib/contracts.ts, src/lib/catalog.ts, src/lib/client-api.ts and src/lib/auth-client.ts until frozen. Every interface uses camelCase JSON. No client imports server modules. Shared types:
- Expression {id:number, phrase:string, principle:string, color:string}.
- RecognitionInput {submittedName:string,recipient:string,message:string,expressionIds:number[],requestKey:string}.
- Recognition {id:string,recipient:string,message:string,expressionIds:number[],createdAt:string,firstPublishedAt:string|null,expiresAt:string,version:number,status:'held'|'published'|'hidden'|'invalid',featured:boolean}.
- AdminRecognition extends Recognition with submittedName:string, reason:string|null.
- Aggregate {periodStart:string,periodEnd:string,recognitions:number,expressionCounts:number[],expressionTotal:number,revision:number}; counts array exactly9 canonical positions.
- DisplaySettings {version:number,mode:'normal'|'quiet'|'neutral',motion:'calm'|'standard'|'lively'|'still',pauseArrivals:boolean,pauseRotation:boolean,collectionOpen:boolean,lowActivityMinutes:number,readingSeconds:number,maxBubbles:number,showTrails:boolean,showConstellations:boolean}.
- DisplaySnapshot {serverTime:string,revision:number,recognitions:Recognition[],aggregate:Aggregate,settings:DisplaySettings,submissionUrl:string}. Recognition status always published, valid, unexpired in display snapshot; never submittedName or private reason.
- AdminSession {id:string,role:'owner'|'moderator',needsMfa:boolean}. Owner email is a protected runtime provisioning input, never fixture or public docs.
- ApiError {error:string,code:string}; client api<T>(path,options?) fetches JSON, throws Error with code/status, handles bearer session where supplied. Error bodies have no request content.

## HTTP contract, backend lane is sole API owner
- GET /api/config -> {collectionOpen:boolean,configured:boolean}; no secrets.
- POST /api/recognitions body RecognitionInput ->201 {id,status:'published'|'held',expiresAt}; same logical retry returns existing receipt.400 validation,429 throttle,503 unavailable. Accepted held has no public count/cue.
- GET /api/admin/session bearer -> AdminSession;401 unauthenticated,403 no membership, owner needsMfa returned but all other privileged operations require aal2.
- GET /api/admin/recognitions?status=&search=&expression=&from=&to=&page= -> {items:AdminRecognition[],total:number}; maximum50 per page, only unexpired. GET /api/admin/recognitions/:id ->AdminRecognition.
- PATCH /api/admin/recognitions/:id -> {expectedVersion:number,action:'edit'|'publish'|'hide'|'restore'|'invalidate'|'feature'|'unfeature'|'delete',fields?:Partial<RecognitionInput>,reason?:string}; returns {recognition:AdminRecognition|null};409 stale,410 expired,403 Owner-only delete. Publish/edit rerun validation. Invalidation and substantive edits require reason category, not copied personal notes.
- GET /api/admin/overview -> {heldCount:number,nearestExpiry:string|null,lastCleanupAt:string|null,overduePurgeCount:number,devices:Device[],aggregate:Aggregate,settings:DisplaySettings}.
- GET /api/admin/reports?period=week|month|all|custom&from=&to= ->Aggregate. custom dates month boundaries only, no per-person data. GET /api/admin/reports/export same period -> aggregate-only CSV.
- GET /api/admin/settings ->DisplaySettings; PATCH same -> {expectedVersion:number,changes:Partial<DisplaySettings>} ->DisplaySettings. Both roles for daily display settings, Owner only collectionOpen. Canonical wording/required nine-page and arbitrary QR destination are not editable.
- GET /api/admin/devices ->{items:Device[]}; POST ->{code:string,expiresAt:string}; DELETE /api/admin/devices/:id revokes; all Owner-only except device read allowed Moderator.
- POST /api/display/pair {code:string} ->{paired:true}, sets Secure httpOnly SameSite cookie. GET /api/display/snapshot ->DisplaySnapshot with no-store. POST /api/display/ack {settingsVersion:number} ->{ok:true}. Revoked/expired device ->401, clear personal state immediately.
- Device {id:string,label:string,lastSeenAt:string|null,appliedVersion:number,revoked:boolean}. No device secret in list/API logs.
- GET /api/admin/members -> {items:{id:string,role:string,active:boolean}[]}; POST {email:string,role:'moderator'} invites; PATCH /api/admin/members/:id {active:boolean} revokes, Owner-only, last Owner protected. No raw key/bootstrap password UI.
