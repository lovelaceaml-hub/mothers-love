## App-only encrypted logical backup and local restore

Approval remains pending for exporting campaign personal data onto Anthony's Mac and restoring it locally. No backup runs in this cloud workspace. Ask approval for exact scope, encrypted destination, retention/deletion date, operator, and whether an encrypted owner-only Drive copy is wanted. The current policy forbids permanent raw backups; encryption does not by itself override that retention policy. Permission for the isolated project and its new credentials/access is still needed; branch preview publication itself is already covered by the test/deploy request.

Scope: all approved tables, sequences, types, routines, indexes and ACLs inside `mothers_love`, including the migration ledger and the settings/weekly-focus rows; only the exact app-owned `public.ml_*` bridge routines with signatures, owners and function ACLs. Record a reviewed object/table allowlist from metadata before export. Exclude every public-schema table and its data, unrelated public functions, auth user/session data, storage objects, cron history, other schemas and global roles/passwords/default privileges. The prior `--schema public,mothers_love --data-only` proposal is too broad and must not be run. Use `pg_dump --format=custom --schema=mothers_love` with existing authorized read access for the app schema, plus catalog-derived definitions/ownership/ACLs for the approved bridge-function list; a schema filter does not include functions in another schema or all external dependencies. Do not invent a table filter for functions or dump all public to solve that limitation. Capture extension/role/dependency metadata without secrets for a local bootstrap. Keep related reads under one held exported snapshot where supported and no competing DDL; verify the manifest against the dump archive before encryption.

Encryption at rest is concrete: create an AES-256 encrypted APFS sparse disk image in macOS Disk Utility, outside Git and cloud-sync roots. Store its password in Anthony's Keychain, separately from the image. Mount it only for export/restore. Put dump inputs, manifests, PostgreSQL data directory, WAL, temp files and private restore logs on that mounted volume; no /tmp or unencrypted Docker named volume for real data. Existing Mac FileVault must be verified for host swap/system spill before a real-data restore; changing host security requires separate permission. `umask 077` restricts filesystem access but is not encryption.

Create the portable encrypted artifact with the installed verified `age` binary and an interactive owner-managed passphrase already stored separately in Keychain: `tar -C "$ML_ENCRYPTED_MOUNT" -cf - app.dump bridges.sql manifest.json | age -p -o "$ML_ARCHIVE.age"`. Manually enter the passphrase at the TTY; do not let age autogenerate and print a secret into captured logs; no passphrase in command arguments, shell history or environment. Use pipeline failure checking and remove incomplete ciphertext on failure. Never create a plaintext tar outside the encrypted mount. Include plaintext file hashes inside the encrypted manifest; store the ciphertext SHA-256 externally. Verify decryption, internal hashes and restore before considering the backup valid. Upload only ciphertext if separately approved; verify its downloaded hash. Unmount and eventually delete the encrypted image according to the approved retention plan. Do not claim secure erasure by rm on an SSD.

Rehearse on a local network-disabled PostgreSQL cluster whose data and logs reside on the encrypted volume. Bootstrap only required extension/schema/platform role names as local NOLOGIN roles, restore with `pg_restore --exit-on-error`, then restore the reviewed bridge definitions and ACLs. Validate object inventory, function signatures/owners/ACLs, indexes, ledger hashes, table counts and referential integrity without printing personal rows. Keep the restored application closed; do not serve personal content, reactivate sessions, send mail, or enable production credentials. If Supabase Auth is needed for a rehearsal, use an isolated local Supabase instance with blank synthetic Auth state and inspect bootstrap requirements first. This app-only backup does not recover the shared project's other apps, Auth identities or Storage; disclose that limitation instead of claiming provider-wide disaster recovery. Test migration/index/rollback only on disposable fictional fixtures unless Anthony separately authorizes running them on the encrypted restored app copy.
