# Reaction contract for implementation

Root contract, reviewed by the Sol planning lane in parallel. User approved one toggleable like per browser without sign-in. Implementation may proceed while the consultant checks race and privacy details; accepted findings are corrected before release.

GET /api/reactions?ids=UUID,UUID accepts 1 to30 unique valid IDs. Returns {items:[{id:string,count:nonnegativeInteger,liked:boolean}]}. Only currently published and unexpired recognitions appear. Neutral returns empty; unhealthy cleanup returns503. Missing items are unavailable, not zero-count placeholders. This endpoint may establish the first server-generated random256bit HttpOnly Secure SameSite=Lax path /api/reactions browser cookie, max age30days. No cookie/token/hash is returned in JSON. PUT never creates browser identity. A blocked-cookie browser receives428 on PUT with a concise recovery message. No persistent personal feed content.

PUT /api/reactions/[id] accepts exactly {liked:boolean}, with existing body-size guard, configured check, explicit trusted Origin required and cross-site rejection. Requires valid existing browser cookie. Returns {id,count,liked} on success. Desired-state semantics make retries idempotent. Missing/held/hidden/invalid/expired target returns404; unhealthy/neutral returns503; invalid input400; invalid origin403; missing cookie428; rate limit429 with Retry-After. UI allows one in-flight mutation per row and uses confirmed state only.

RLS enabled and forced, no table grants to runtime or common public roles. New dedicated hardened public reaction-read and desired-state-write functions only, SECURITY DEFINER emptysearchpath, explicit schema names and bounded inputs; revoke PUBLIC/anon/authenticated/service_role execute, grant mothers_love_runtime. Existing001..004 and their functions remain untouched.

Getter counts eligible rows and whether the hash is present, returns only id/count/liked. Setter performs an unlocked settings/cleanup precheck, locks the eligible recognition FOR UPDATE, then settings FOR SHARE and rechecks health and eligibility, inserts ON CONFLICT DO NOTHING or deletes only its own pair, then returns count under the recognition lock. Concurrent duplicate and opposing requests must leave at most one row; hide/purge races cannot recreate expired/deleted data. No adjustment to campaign totals, feature priority, ordering or lifetime. Reaction rows cascade on existing purge/permanent deletion, no additional cron.

Use existing rate_limits table under distinct reaction_ip and reaction_browser scopes with hashed IP and cookie identity only,24hour expiry handled by existing purge. Proposed bounded write limits120/IP/minute and30/browser/minute with atomic upserts and Retry-After60, independent of submission budgets. No new provider secret. Cleared browser storage and use of another browser remain a documented limitation of anonymous likes; this is not verified-person voting.

Minimum proof: exact projection and request validation, strict origin/cookie gates, read/write eligibility and neutral/cleanup gates, idempotent repeated true/false, separate browsers count independently, no table/common-role access, runtime execution, actual concurrent duplicate writes and hide/purge contention, FK cleanup, unchanged aggregate totals and existing function fingerprint. All positive writes use isolated synthetic PostgreSQL fixtures; production checks are read-only.
