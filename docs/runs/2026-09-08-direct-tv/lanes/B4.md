# B4: Public snapshot admission bound

## Scope

Per-instance admission protection for the unauthenticated public TV snapshot read. This lane owns the route guard, its focused tests, and this record only.

## Technical decision

Before each database query, the route uses a process-local token bucket keyed by a transient SHA-256 client identifier only when Vercel confirms its deployment environment and provides its forwarded IP header. The normal default permits 180 requests per minute per IP with a burst of 24, which accommodates several TVs polling every five seconds from one church network. The guard caps each instance at 12 in-flight snapshot queries, bounds stored key state to 512 entries, and expires idle entries after ten minutes.

When a request is refused, the route returns `429`, `Retry-After: 5`, and `Cache-Control: no-store` before opening a database query. Every admitted request releases its slot in `finally`, including transport or projection failures. This is deliberately a per-instance limit, not a distributed quota across Vercel instances. It stores no raw IP, has no database writes, and does not cache snapshot content.
