# B5: Bounded public display database query

## Scope

Sol fallback implemented the final native controller finding after the Terra correction sequence. Owned source was limited to the public display query, its route, and focused backend tests in `$HOME/Projects/mothers-love-worktrees/direct-tv-timeout`.

## Result

Commit `ffa683b00d69cbf85fe353f27b84965bd8b525bd` runs each public display snapshot query in a PostgreSQL read-only transaction. The transaction sets `statement_timeout` locally to `5000ms` before calling `public.ml_public_display_snapshot`. PostgreSQL now ends a blocked or sleeping display statement before the browser's 10-second request deadline. The local setting ends with the transaction and cannot leak to later database work.

The route rejects an already-aborted request before admission or database access. The query checks the request signal again after waiting for a transaction connection and after installing the statement deadline, so an abandoned queued request does not run the snapshot query. Every route path still releases its admission slot and returns the existing uncached 503 response for database or abort failures.

`PendingQuery.cancel()` was deliberately omitted. The installed postgres.js documentation warns that its separate cancel connection can race with connection reuse and cancel a later query. The server-side statement deadline supplies the reliable bound without that late-cancel risk.
