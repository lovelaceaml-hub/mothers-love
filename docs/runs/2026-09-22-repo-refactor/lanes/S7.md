## Method

Every split was made by a script, not by hand, and every script is saved with the evidence. Four kinds of cut were needed, from least to most scaffolding:

1. **Whole declarations** (`split-top.mjs`). Top level statements move byte for byte into sibling modules; the TypeScript checker works out each module's imports; a declaration another module needs gains `export`; the original file re-exports every name it exported before, so no importer changes. The script refuses any import cycle.
2. **Blocks of one large function** (`extract-blocks.mjs`). For a builder written as one closure (the classic districts, the classic scene, the design world, the kit builders), its shared preamble becomes a factory whose return type is the one shared type the plan asked for (`HeavenlyDistrictKit`, `LegacySceneKit`, `DesignWorldBase`), and each block of statements becomes a function in its own module, receiving that object and returning what later code reads. The blocks are called in their original order, so every seeded random sequence, object id, material id and scene graph position is unchanged. The script refuses a block that returns, breaks or continues across its edge, uses `this`, reassigns an outer variable, or reads a `let` the function reassigns anywhere (a copy would go stale).
3. **Class methods** (`split-class.mjs`). A long method becomes a function typed `this: TheClass` in another module, body byte for byte, and the class keeps a one line forwarder with the method's own signature, so the class's API and every call site stay. Arrow handlers stay arrow fields, so `setAnimationLoop`, the event listeners and the resize observer receive the same function objects as before. TypeScript lets only a class's own body read `private` members, so `private` is dropped from exactly the members the lifted code reads: a type level change with no runtime effect, and each class's doc says so.
4. **React** (`extract-blocks.mjs` and `extract-jsx.mjs`). The page's hooks move, in order, into one custom hook, so React sees exactly the same hook calls. Five children of the page's `<main>` move into render functions called in the same place, each returning exactly the value its child produced: no wrapper fragment and no new component, so the element tree React receives is unchanged.

Indentation: bodies lifted out of a class or out of JSX lose one level of indentation, except inside template literals, which are never touched, so every shader string is character for character the same.

**Proof that each split is a move** (`move-check.mjs`, committed as `scripts/review/move-check.mjs`): every non-import line of the old file at `b04e4be` must reappear in the union of the new files, as many times as it appeared, compared after trimming indentation and ignoring an added `export` or a dropped `private`; every new line that did not exist before is listed. The reports are in the evidence folder.

### Decisions made inside the envelope, for the reviewer

1. **Blocks of one function became functions.** The plan's table (one module per district, per location, the React shell and its panels, the engine's construction, frame loop and disposal) cannot be met by moving whole declarations, because those files are one function or one class. The blocks keep their text; the scaffolding is a factory, a signature, a return and a call per block, all listed in the move checks. The byte identical captures are the behaviour proof.
2. **`private` dropped on members the lifted methods read** (43 in `StudyPearlSkin`, 48 in `WorldRecognitionBubbles`, 84 in `WorldEngine`, counted as the fall in `private` modifiers between `cc606ce` and the final head). TypeScript offers no other way for a function outside a class body to read its members. Runtime is identical; each class's doc names the files that read them.
3. **Preparation moves in `design-world.ts`.** The live `disposed`, `sparkles` and `trails` lets and `invalidate` moved below the shared base, and the local `Crowns` type moved to module level, so the base could be lifted without handing a reassigned let to another function. The Sanctuary block stays in `createDesignWorld`, because its heart loader reads the live `disposed` when the model arrives.
4. **The coordinator keeps its entry file.** `coordinator.ts` re-exports every name it exported, so `/display`, the admin preview and the TV's tests import exactly as before.
5. **Dead code found, left as it was:** `currentMode` in the coordinator and `invalidate` in `applyKitLayouts` are declared and never used. Moves only, so they stayed; a later plan can remove them.
6. **The tool fix inside the section.** An early version of the block tool returned an extra, unused `kit` field from `design/base.ts`; it was removed in `e36e366`, and the move check covers the final state.

## Limitations

1. **The capture harness is not perfectly deterministic.** Two runs of one build differ on pixel row 995 at channel value 1 in one to three stills and by a few scattered channel value 1 pixels in `design-welcome`. Every difference seen after the split is also seen between two runs of the same source, before or after, and one after run matched Section 5's durable captures in every still byte for byte. The acceptance line "captures byte identical" is therefore met in that sense, not as a guarantee that any two runs match.
2. **Three files are over 400 lines** (`WorldContent.tsx` 444, not in scope; `kit-neighbors.ts` 430; `world-engine.ts` 401). Taking `kit-neighbors.ts` lower means cutting its builder's pair loop out with a typed signature, more scaffolding for 30 lines; it is left for Section 8 to judge.
3. **The class pattern.** Methods lifted into functions typed `this: TheClass` with forwarders are faithful to the moves-only rule but unusual. The members they read lost `private` at type level (175 modifiers across the three classes). A later plan could turn each group into a collaborator object, which is a real refactor and not a move.
4. **Render functions, not components.** The five page children are plain functions so React's element tree is unchanged. Turning them into components is a later choice; it changes the tree though not the page.
5. **Dead code kept:** `currentMode` in the coordinator and `invalidate` in `applyKitLayouts` are unused and were moved, not removed.
6. `tests/world/world-preview.spec.ts` (the Playwright journeys) was not run, as in Section 5. The live mode run against a preview was not repeated; this section changes no behaviour, and pushing the branch reruns #19's cinematic CI check and builds a preview.
7. The Mac's load average was 12 to 55 during the harness runs, which matters only for frame timings, none of which this section reports.
8. Effort xhigh was confirmed from the session's own settings. No Gemini fallback was used; the mechanical work ran as scripts.
