### Finding: a GitHub branch rename closes a pull request the branch heads

GitHub's branch rename API retargets a pull request whose **base** is renamed, but it does **not** follow a pull request whose **head** is renamed. Renaming `feature/world-cinematic-art-pass` to `feat/world-cinematic` closed draft PR #8 immediately. It could not be reopened (`GraphQL: Could not open the pull request`) because a closed pull request cannot be reopened once its head branch name no longer exists, and polling for a minute confirmed GitHub's background job does not repair it.

Nothing was lost. The head commit `e8e0c47` was never orphaned; it sits on `feat/world-cinematic` throughout. PR #8 carried 0 review comments and 1 issue comment. The work continues as **draft PR #10**, created with PR #8's exact title and body plus a provenance note, and #8 carries a comment pointing at #10.

The cheaper order for anyone repeating this: create the replacement pull request first, or rename head branches only when no pull request heads them. Plan 26 Section 5 should target **#10**, not #8.
